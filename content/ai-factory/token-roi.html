The Slide

Where the Tokens Go — and Where They Stop

Each rule category addresses a distinct vector of token bloat. Together they compound to deliver 72 % session-level savings.

Before Rules
~20,000 tokens / session
  • All 38 rules injected into every context window regardless of task type
  • Unlimited file reads — agents load 15+ files per task by default
  • Verbose RESULT JSON — full prose, stack traces, file contents pasted inline
  • Rule content re-stated in every response — duplicating what's already defined
  • Multi-paragraph chain announcements — explaining every procedural step
  • No output sanitization — API response bodies, DB rows written to logs
With Rules Active
~5,600 tokens / session
  • 8 core + ~3 conditional rules — only what's relevant to the task type loads
  • Hard file-read caps — 3 (haiku) / 6 (sonnet) / 10 (opus) maximum per task
  • Compressed RESULT format — 3 fields for LOW, 5-bullet MEDIUM, full only for HIGH
  • Deduplication enforced — rules referenced by name, never restated inline
  • One-line auto-chain — zero prose overhead for task transitions
  • Output sanitization active — file contents, secrets, API bodies blocked from logs

Rule-by-Rule Impact Breakdown

Context Budget context-budget.md

Conditional rule loading — only 8 always-on rules; 22 codeguard rules gated behind file-type conditions. File read caps prevent unbounded context expansion.

  • • Without: 38 rules × ~200 tok = 7,600 tokens rule overhead
  • • With: 11 rules × ~200 tok = 2,200 tokens — a 71% drop
  • • File cap: 15 → 6 avg reads × 500 tok = 4,500 tokens saved
Overhead reduction71 %
~9,900 tok saved / session
Result Compression result-compression.md

Tiered output format — LOW tasks emit only 3 fields; MEDIUM capped at a 5-bullet details list; verbose mode reserved for HIGH complexity only.

  • • Without: ~1,500 tokens per result (prose, full stack traces, duplicated spec)
  • • LOW result: ~180 tokens  |  MEDIUM: ~400 tokens
  • • Mix assumption (70% LOW, 25% MEDIUM, 5% HIGH) → ~1,100 tokens saved per task
Output verbosity cut73 %
~1,100 tok saved / task
Output Sanitization output-sanitization.md

Block high-volume content sinks — file contents, API response bodies, and DB rows are banned from result and log files. Reference by path only.

  • • Without: file dumps add 500–3,000 tokens to each result arbitrarily
  • • With: content replaced by paths + aggregate counts → avg 600 tokens saved
  • • Prevents runaway log inflation across .comms/ and .session-logs/
Log bloat eliminated~80 %
~600 tok saved / task
Deduplication context-budget.md §Deduplication

Reference rules by name only — if a spec re-states a loaded rule, the restated version is ignored and canonical rule governs. AI responses cite rule ID, never paste body.

  • • Without: rules re-stated in-thread add ~300–600 tokens per repeat
  • • With: one-word cite (e.g., "following core-context") replaces 400-word explanation
  • • Estimated ~350 tokens saved per task on average
Repetition eliminated~40 %
~350 tok saved / task
Auto-Chain Protocol auto-chain.md

One-line announcements only — task transitions emit a single structured line. No preamble, no re-explanation, no "permission-asking" overhead between chained tasks.

  • • Without: 3–5 sentence transition prose per task handoff (~200 tokens)
  • • With: single auto-chain line (~15 tokens) × 10 chain depth = ~1,850 tokens saved / chain
  • • Session depth cap (10 tasks) also prevents runaway token accumulation
Verbosity reduction~93 %
~185 tok saved / handoff
Session Activity Log session-activity-log.md

Structured log format with content restrictions — logs contain only titles, file paths, and plain-text descriptions. No code snippets, no response bodies, no PII.

  • • Without: unstructured logs balloon to 2,000–5,000 tokens per entry
  • • With: structured template caps each log at ~300 tokens
  • • Eliminates future session warm-up overhead from oversized history files
Log size reduction~85 %
~300 tok saved / log entry
